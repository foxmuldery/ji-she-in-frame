# 1000 次模拟试玩报告

工具：`./dev/sim.sh [n]`（默认 1000）。  
实现：`dev/sim/player_sim.js`（仅 `index.html?sim=N` 时动态加载，`dev/` 不进发布包）。

## 方法

模拟器直接驱动游戏状态机，而不是脚本化的假流程：

- 移动走真实的 `blocked()` 碰撞与 `advanceMovement()`，用 BFS + 安全间距规划路径。
- 交互走 `interact()` / `setCamera()` / `takePhoto()` / `commitRitual()` / `startReview()`，与键盘实际调用同一批函数。
- 时间走 `state.time += dt` + `tickJobs()`，`later()` 定时器真实推进。
- 每局随机化：是否跳过看带、是否先摆错一遍供桌、是否走错一个找点、是否躲错方向、是否接错手、结局走 help/film、是否进坏结局。
- 35% 的局注入「捣乱玩家」：随机暂停/继续、开关记录本、开关 DV、空按 E/L/Space/R、反复进出回看。
- 渲染/HUD/音频用 `FUZZ_ACTIVE` 短路，因此 1000 局约 5 秒跑完。

## 结果（1000 局）

| 指标 | 数值 |
| --- | --- |
| 到达结局 | 996 / 1000（99.6%） |
| 结局分布 | 帮助 669 · 胶片 219 · 坏结局 104（+ 4 局在结局后仍在跑） |
| 单局时长（游戏内） | p10 31.2s · **p50 99.1s** · p90 108.3s · max 125.6s |
| 异常 / NaN / 坐标越界 / 电量越界 | 0 |
| 未捕获异常 | 0 |

分章中位时长：第 1 章 37.3s · 第 2 章 11.9s · 第 3 章 17.4s · 第 4 章 10.3s · 第 5 章 + 结尾 19.2s。

## 发现并修复的问题

### 1. 跳过开场对话会永久锁死 DV（严重，已修）

老流程里 `setCamera()` 用 `talked || nearWoman()` 判断能否举机。如果玩家走到老妇身边**直接按 F、没有先按 E 说话**，`talked` 永远是 false：

- 一旦触发「她回头」，`interact()` 走的是 triggerUncanny 分支，不再补 `talked`；
- 之后在香炉/水碗/门框（离她 3 米以上）按 F 一律提示「先走近她」；
- 第 1 章的三次显影与三张照片无法完成 → 只能重开。

修复：改成只在**第一次举机**时要求靠近/对话（复用原本闲置的 `state.firstCameraDone`），并在首次举机时置位。  
回归测试：`runTest()` 新增 `cameraAfterIntro`（`talked=false` + 远离她时仍可举机），自测 52/52。

### 2. 捣乱输入下的边界（未构成硬锁）

- 黑屏过渡中按 Esc → 暂停被排队，过渡结束后才弹出（`pauseQueued` 已有处理，实测可恢复）。
- 回看被外部操作提前关闭时，第 3 章「闭眼帧」门槛不会丢：重新按 R 回到 00:41:17 再退出即可推进。
- 拿着 DV / 记录本打开时按 E、Space 会被正确拒绝，不会吞状态。

剩下 0.4% 未到终点的局全部发生在「连续暂停 + 反复开关 DV/记录本」的极端组合下，且均为可恢复状态，没有出现卡死、状态错乱或异常。

## 优化建议（按收益排序）

1. **时长与「10–15 分钟」目标差 6–9 倍**：当前中位 99 秒。要么补 4–6 个等量章节，要么把商店页/标题页的目标时长改写为「约 2 分钟垂直切片」，避免预期落差。
2. **第 1 章占 38% 时长，主要是跑图**：三个供品点分居房间三角，单局要横穿房间 4–5 次。把门框/线轴挪近供桌，或把显影判定半径 2.1→2.6，可省 6–8 秒且不降低紧张感。
3. **电量机制目前不构成压力**：各章开局中位电量 100，全程最低 24（拍照门槛 16）。要么调低回充/提高单次耗电，让「省电」成为真实决策，要么弱化 HUD 上的电量焦虑。
4. **第 2 章 11.9 秒偏短**：三个找点几乎直线可达，可加一次「她在移动」的中间态，把节奏拉到 20 秒左右。
5. **坏结局触发率 10.4%**：对首次玩家偏高（三次摆错即进）。可把第一次摆错改成提示 + 重试，第二次才计数。

# 零知识首次游玩 100 局（v2.10）

工具：`index.html?nointro=1&naive=100&pace=human&nraw=1`（实现 `dev/sim/naive_sim.js`）。  
"零知识" 的定义：不读答案、不读藏点、不读规则；只读屏幕上的 `#prompt` / `#subtitle` /
`#chapterHud` / `#case`，所有输入是真实的 `KeyboardEvent`。

`pace=human` 按字幕字数加入阅读停顿（0.8s + 0.085s/字，上限 3.4s），用来区分
"机器的反应速度" 和 "人读两行字" 的差别。

## 结果

| 组 | 通关 | 坏结局 | 放弃 | 中位时长 |
| --- | --- | --- | --- | --- |
| 阅读节奏（`pace=human`） | 100/100 | 0 | 0 | **9:38**（p10 8:53 · p90 10:42） |
| 机器人节奏（无停顿） | 99 help + 1 film | 0 | 0 | 6:14 |

分章中位（human）：第一遍 3:54 · 第二遍 0:55 · 第三遍 1:18 · 第四遍 1:04 · 第五遍+走廊+暗房 1:34 · 回看与结局 1:00。

> 2026-10-22 复测（v2.10）：第二幕「暗房」加入后重跑 100 局，100% 通关，中位 8:24 → 9:38（净增约 74 秒）。
> 结局分布 help 94 / film 6，与 v2.9 一致——新房间没有改变玩家的结局倾向，只加长了“看清”的时间。
>
> 暗房段（模拟）：进入 → 三处显影 → 开剪 → 对缝 1–3 次 → 空格 → 洗印 → 推门，中位约 62 秒，
> 其中对缝平均 2.6 次按键往返（容差 ±3%，每步 2.2%）；没有任何一局卡死或需要重来整段。

## 修掉的问题

1. **回看/走廊里 DV 既不充电也不耗电**：低电量时开着带子等回电会无限等；模拟玩家
   在第 3 章因此放弃。现已在回看前先处理帧门，且文案提示退出回看。
2. **重复显影没有回声**：`completeCameraScan()` 对已显影物件直接 return，补拍时屏幕
   无反应，玩家误判 "这里没东西"。这一条仍是建议（见下）。
3. **走廊是纯 W**：加入走廊自己的 DV（侧门 / 遗像 / 门牌），并把电话接听挂在
   "看清门牌" 上；否则玩家会一路 W 到底，走廊只值 11 秒。

## 仍建议优化

- 显影与快门合并（或已显影免快门）：第一遍约 45 秒是纯往返 + 等电。
- 取景器吸附：目前需要对准，模拟玩家每局约 2 次空按。
- 重复显影应回一句 "取景器：香三炷。（已记录）"。
- 电池：每局都会掉到 0%，充电 1.4%/s 偏慢。
